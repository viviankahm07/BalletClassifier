Technical Design · ML Pipeline

Ballet Pose Classifier

A pose-estimation pipeline that identifies ballet positions from a single photograph — trained on joint angles rather than raw pixels, with a feature-group-aware classifier and a Streamlit demo for live inference.

Image → MediaPipe pose estimation → 33 3D keypoints → 24 joint-angle features → feature-group-routed classifier → predicted position with a full confidence breakdown across 19 classes.

Overview

Executive Summary

Rather than training a CNN directly on pixels, this pipeline extracts skeletal keypoints with MediaPipe and converts them into joint angles before classification. That single design choice — features over pixels — is what makes the rest of the system possible on a comparatively small, self-collected image set: the model doesn't need to learn what a dancer or a studio looks like, only what a knee angle of roughly 160° combined with a hip abduction of 45° means.

Why joint angles, not pixels

Angle-based features are rotation-invariant (work from any camera angle), scale-invariant (work regardless of distance from camera), and — with sorted left/right pairs — side-invariant, so a left arabesque and a right arabesque collapse into the same training example instead of needing to be learned separately.

Goals & Non-Goals

Goals

  • Classify a single uploaded photo into one of 19 ballet positions with a calibrated confidence score per class.
  • Generalize across camera angle, dancer distance, and left/right symmetry without needing separately labeled mirror-image classes.
  • Train well on a comparatively small, self-collected dataset by using a compact, hand-designed feature space instead of raw pixels.
  • Compare multiple classical ML classifiers head-to-head and track every run for reproducibility.

Non-Goals

  • No video or multi-frame temporal input — single-image inference only.
  • No multi-dancer detection — MediaPipe uses the first person it detects in frame.
  • No deep learning on raw pixels — the design deliberately avoids needing a large labeled image corpus.
  • No mid-transition pose recognition — designed for clear, held positions.
Structure

System Architecture

The pipeline is a linear feature-extraction chain feeding a routed ensemble of classical classifiers, not an end-to-end neural network — a deliberate choice given dataset size.

End-to-End Pipeline

1
Pose extraction
MediaPipe's pose_landmarker_heavy model extracts 33 3D keypoints per image. Images where no pose is detected, or where landmark confidence is too low, are reported and skipped rather than silently guessed at.
2
Normalization
Keypoints are centred on the hip midpoint and scaled by torso length, removing the dancer's position and size in frame before any angle is computed.
3
Feature engineering
Keypoints are converted into 24 joint angle features — 12 directional angles, 4 symmetric arm angle pairs, and 8 symmetric leg angle pairs.
4
Dataset build
Feature vectors are split into train.csv, val.csv, and test.csv, with class labels saved to label_classes.npy.
5
Training & comparison
Four classifiers — Random Forest, SVM, Gradient Boosting, and an MLP — are trained and compared in a single run, each logged to MLflow with parameters and metrics.
6
Inference
The best-performing model is saved and loaded by both the Streamlit demo and the CLI predictor, returning a predicted class with a full per-class probability breakdown.
Feature Design

Joint Angle Features

The model uses 24 joint angle features per image, chosen specifically to encode the geometry that distinguishes ballet positions while discarding everything that doesn't.

Feature group Count Description
Directional angles 12 Left/right knee, hip, elbow, shoulder, ankle, and hip abduction (turnout) — kept separate by side where the distinction matters.
Symmetric arm angles 4 Sorted left/right pairs, so an arm raised on either side looks identical — used for third and fourth position.
Symmetric leg angles 8 Sorted left/right pairs, so either working leg looks identical — used for all one-legged poses (arabesque, attitude, passé, etc.).

Feature-Group Routing

A single flat classifier trained on all 24 features would let irrelevant angles add noise to positions that don't depend on them. The GroupedClassifier instead routes each pose family to a sub-model that only sees the angles relevant to distinguishing within that family.

Group Features used Classes
leg_focused 8 symmetric leg angles tendu, dégagé, arabesque, attitude, passé, penché, pliés, fondu
symmetric_body 8 symmetric leg + 4 symmetric arm angles third, fourth position
full_body all 12 directional angles first, second, fifth position

Components

Models & Experiment Tracking

Four classical classifiers are trained and compared in a single run rather than committing to one architecture upfront — reasonable given the feature space is low-dimensional (24 features) and the dataset is comparatively small, where classical models often match or beat deep architectures.

  • Random Forest — the shipped baseline model, robust to the noisiest keypoint detections.
  • SVM — strong on the lower-dimensional, well-separated feature space.
  • Gradient Boosting — captures non-linear interactions between joint angles.
  • MLP — a small neural baseline for comparison against the classical methods.

Every run's parameters and metrics are logged to MLflow, and the best-performing model is saved automatically to models/saved/ — the demo and CLI both load the most recently modified .pkl, so a newly trained model is picked up without any manual wiring.

Key Design Decisions

Decision Rationale
Joint angles over raw pixels Makes the classifier rotation-, scale-, and side-invariant by construction, and lets it train well on a small, self-collected image set instead of requiring a large labeled corpus for a CNN.
Sorted left/right feature pairs Collapses mirrored poses (a left arabesque and a right arabesque) into a single training example instead of needing separately labeled classes for each side.
Feature-group-routed classifier Prevents angles irrelevant to a pose family from adding noise — a two-legged position classifier never sees single-leg working-leg angles it has no use for.
Four classifiers trained per run, best one kept Removes the need to guess the right model family upfront; classical models are compared empirically rather than assumed.
Explicit "no pose detected" failure mode The app reports when no skeleton can be found rather than guessing on a low-confidence detection, which keeps the confidence scores it does report meaningful.

Supported Positions

19 positions across five categories, defined in data_config.yaml. Adding a new position means adding it to the config, listing it under the correct feature group, and creating its raw-image folder — classes with no image folder are skipped with a warning rather than failing the run.

Category Classes
Positions first, second, third, fourth, fifth position
One-legged arabesque, attitude derrière, attitude devant, passé, penché
Tendu tendu devant, tendu à la seconde, tendu derrière
Dégagé dégagé devant, dégagé à la seconde, dégagé derrière
Two-legged demi plié, grand plié, fondu
